---
title: Staying signed in
date: 2026-09-09
---

A fix for 1.6.0, and an apology for the shape of it. Signing in worked; quitting
Neo undid it.

The upgrade to 1.6.0 had three things to do once: sign this Mac out, because the
sync server's accounts had been reset and the old token could not work; forget
how far it had read, because the old cursors counted batches that no longer
exist; and forget which files it had already uploaded, because they were stored
under names nothing can find any more.

All three were correct. None of them were guarded, and Neo applies its
migrations **every time it opens** — so every launch signed you out again,
threw away your place, and offered every file afresh. You could connect, watch
it work, quit, and find the Sync pane back at the beginning.

They now happen once. A database that still has the old operation log in it has
never been through the upgrade; one that does not is either new or has been
through it already, and both of those want leaving alone.

## What changed

- **Signing in survives a restart**, along with how far each workspace has been
  read and which files have already gone up.
- **Nothing is re-uploaded** on the next launch.

The test suite now opens the database twice and insists that everything a
signed-in machine holds is still there — a rule for anything once-only added
later, not just for these three.
