---
title: Offline again
date: 2026-09-10
---

Neo keeps your work in a database in your home folder and reads nothing over a
network. That has been the point since the first version, and for the last few
it has not been true: a Mac with Wi-Fi switched on but joined to nothing opened
a project and sat on *Loading…* for ever. Starting Neo in that state was worse
still — the splash never lifted at all.

The database was never the problem, and neither was your work. The layer above
it was. The library Neo uses to fetch a screen's data assumes every fetch is a
request to a server, and by default it refuses to start one while the machine
says it is offline: it **pauses** the fetch rather than failing it, so it never
answers and never complains. Every screen here reads "no answer yet" as "still
loading", which is exactly what you saw.

Nothing Neo reads has ever been a request to a server, so nothing it reads asks
about the network any more. Writes too, and those mattered more: a paused write
looks like an item you created that quietly was not.

Syncing is unaffected. It is the one part of Neo that genuinely needs a network,
it has always known when it does not have one, and the strip that says so is
still the only thing in the app that mentions it.

## Where a to-do actually lives

Today is a list of things gathered from everywhere — a card on a board, an item
a meeting left owing — and the question it raises about any one of them is
*where did this come from*. Right-click one now and Neo will take you to it.

- **Show on the board** goes to the card itself, not to the board it is
  somewhere on.
- **Show in the meeting** appears when the item came out of a room, and goes to
  the write-up it was agreed in.

Whichever you pick, the thing you were sent to lights up for a moment when you
arrive, so you land on it rather than starting a search of a screen with forty
cards on it. The same is true going the other way: *Show on the board* on a
meeting's to-do now points at its card instead of leaving you at the board.
